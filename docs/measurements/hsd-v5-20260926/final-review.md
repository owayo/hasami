# 文法共有 v5 実装の独立レビュー

2026-09-26。独立した Codex 担当が、`astro-sight review --dir . --git` から始め、
`src/hsd/` の差分、`tests/hsd_grammar.rs`、`scripts/hsd-format-eval.rs`、
`scripts/hsd-format-compare.py` と設計書を確認した。コードは変更していない。
計測中の CPU 負荷を増やさないため、このレビューではビルド・テストを実行していない。

## 判定

本番コードと回帰比較器に、採用を妨げる問題は見つからなかった。
性能計測・上流ソースからの再構築・make ci・配布辞書の受け入れ検査は主担当が進めており、
それらが採用条件を満たすことを条件に、本番採用に賛成する。

## 確認した点

- 文法表は必須セクション 18、6B の Pod 要素、FEATURES の番号は u32 LEB128。
  既存 v4 を明示的に拒否するため、旧リーダーによる誤読を避けられる。
- 頻度は重複排除後の素性で数え、同率は 3 番号の辞書順になる。
  元の素性順を保って番号から新オフセットへ置き換え、候補順・同点の扱いには触れていない。
- 正準キーの中間領域は usize のオフセット、最終 FEATURES は u32 の範囲で検査する。
  文字列の長さも checked conversion に変更されている。
- GRAMMAR の長さ・整列・空表・文字列表への参照はロード時に検査する。
  素性中の文法番号はアクセス時に 5B 上限・u32 オーバーフロー・範囲外を検査する。
  flags・カタカナ・UTF-8・文字列長は既存の検査を維持している。
- GRAMMAR を読む typed 呼び出しはロード時の try_cast_slice 検査に対応している。
  素性オフセットのレコード境界自体を保証しない点は、設計に明記した従来仕様と同じ。
- 65,536 組超と varint 境界、頻度同率、欠落・端数・参照破損・v4 拒否の検査が追加されている。
- dump は全 Token フィールドを長さ付きで直列化する。compare.py は逐次バイト一致を検査し、
  SHA-256 の一致だけで判定しない。子プロセスの終了コードも確認するため、両方が失敗した結果を
  正常な一致として扱わない。

## 計測値を記録するときの注意

`eval load` は同じプロセスで Analyzer を 31 回作り直す。
その中央値は「新しい Analyzer のロード＋初回解析」であり、「初回プロセスのレイテンシ」ではない。
OS のページキャッシュに加え、アロケータの状態も後続の反復に引き継がれる。
初回プロセスの時間・RSS は別の `/usr/bin/time` 実行で取り、この反復値と区別して記録する。
QoS は P コアへの厳密な固定ではないため、固定したとは記述しない。

公開済み v4 の配布辞書と新しい v5 リーダーは互換でない。
今回リリース公開をしないことと、v5 辞書を上流から再構築する移行手順を利用者向け文書に残す。

## 負荷停止後の性能測定を受けた採用判定

主担当が測定を最初から取り直した `bench.jsonl` 108 件と `summary.json` を確認した。
以前の高負荷時のログは判定に使っていない。
3 辞書 × 2 コーパスの各組で v4 / v5 / fixed の実行順が 6 通りになっていることを確認し、
同じ回の v5/v4 CPU 時間比の中央値と、各方式の CPU 時間中央値の比を独立に再計算した。

| コーパス | 辞書 | 同じ回の CPU 時間比の中央値 | CPU 時間中央値の比 |
| --- | --- | ---: | ---: |
| mixed | ipadic | -0.28% | +0.25% |
| mixed | ipadic-neologd | -4.44% | -2.25% |
| mixed | ipadic-neologd-sudachi | -0.83% | +0.73% |
| short | ipadic | +1.06% | +1.26% |
| short | ipadic-neologd | -1.54% | -1.76% |
| short | ipadic-neologd-sudachi | +1.09% | +1.69% |

どちらの集計でも持続的な 3% 以上の退行を示す結果は出ていない。
個別の回には +3% を超える値もあり、NEologd の mixed は約 -9.53%〜+4.96% と揺れるため、
「必ず高速になる」「統計的に 3% 未満と証明した」とは判断しない。
「今回の測定では速度は同程度で、持続的な 3% 以上の退行は観測されなかった」とする判断に賛成する。

mixed の最大 RSS の中央値は 3 辞書とも減少している。
非圧縮サイズの削減 9.01% / 6.85% / 7.06% と合わせ、容量の改善が実測に現れている。
fixed が常に速い結果ではなく、varint は推奨辞書で fixed より約 3.2 MiB 小さく、
文法情報を 65,536 組以下に制限する必要もない。今回の選択として varint を支持する。

全 Token フィールドの回帰一致、make ci 成功、上流ソースからの v4/v5 再構築完了は主担当の報告で確認した。
この追記時点では、ロード測定、完成辞書の圧縮比較、再構築した最終辞書の受け入れ検査は継続中。
これらで新たな問題がなければ、文法共有 varint 方式を本番採用してよい。
圧縮後の削減量は展開後の削減量とは別に記録する。

## 残りの検証完了と最終承認

主担当から次の完了報告を受け、未完了としていた条件を確認した。

- 同一プロセスで 31 回測った新しい Analyzer のロード＋初回解析の wall 中央値は、
  v4 → v5 の順に 937 → 844、1,087 → 1,085、934 → 969 µs。
  推奨辞書は 35 µs（約 3.7%）増えているため、ロードもすべて改善したとは記録しない。
  解析コーパスでの継続的な退行は観測されず、この絶対時間差は容量削減と合わせて採用を妨げないと判断する。
- 別プロセスの CLI は約 0.01〜0.05 秒で、表示精度が粗いため微小差の根拠にはしない。
  その RSS は約 0.1 MiB 増加した。大規模コーパスの RSS 削減とは分けて記録する。
- 完成した辞書の zstd -19 圧縮サイズは、v4 → v5 の順に
  5,885,510 → 5,827,281 B、67,674,985 → 66,917,486 B、
  72,540,617 → 71,750,573 B。3 辞書とも約 1.0〜1.1% 減少した。
- 上流から再構築した v4 を変換した期待値と、本番 v5 の全 18 セクションが 3 辞書とも一致した。
  元の実験辞書と再構築品も hasami_version メタデータ以外は同一だった。
- 3 辞書の info --verify、配布辞書の受け入れテスト、文分割の例外表の一致、
  format_version=5 の目録の生成がすべて成功した。
- リポジトリ内の作業用辞書は v5 へ atomic に更新済み。
  docs/hsd-format.md 第 10 章、docs/hsd-v5.md、スキルの現行仕様への参照も更新済み。

以上で、今回の文法情報共有 varint 方式について採用条件はすべて満たしたと判断する。
本番形式 v5 としての採用を承認する。公開リリースを実施したという意味ではない。
