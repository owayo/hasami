# カタカナ発音差分の実験設計（2026-10-04）

基準コードは `fefb950`、辞書は公開リリース `v26.9.107` の v5 配布品。
第 9 節で試算した発音差分を、カタカナ詰めだけに限定して実装し、採用に値するか確かめる。
辞書内容の修復、trie の変更、文法番号や候補の並べ替えは行わない。

## 表現

v5 の仕様は [hsd-v5.md](../../hsd-v5.md) と `src/hsd/*.rs` を引き継ぐ。
コンテナ・18 セクション・64B 整列・リトルエンディアン・上限・中間辞書の flags は同じ。
素性の flags bit4 を発音差分に割り当てる。

bit4 は bit2 と bit3 がともに 1、bit1 が 0 の場合にだけ有効。
読みも発音も U+30A0〜U+30FF の 1B 表現で、両者が異なる場合だけ対象とする。
発音の長さ＋本体の代わりに、次を置く。

```text
prefix_len: u32 LEB128
suffix_len: u32 LEB128
replacement_len: u32 LEB128
replacement: bytes[replacement_len]
```

長さは詰めたバイト数。発音は `reading[..prefix_len] + replacement + reading[len-suffix_len..]`。
書き手は最長の共通接頭部を取り、その残りから最長の共通接尾部を取る。
接頭部と接尾部は重ねない。3 個の varint と置換列が従来の長さ＋発音より
厳密に短いときだけ差分を使い、同じ長さなら従来表現を使う。
UTF-8 の差分、原形の差分、全体の文字列共有は試さない。

## 検査と借用

- 既存の最大 5B・u32 の varint 検査、文法番号の範囲、flags の未知ビットの拒否を維持する。
- `prefix_len + suffix_len <= reading.len()` を checked arithmetic で検査する。
- `prefix_len + replacement_len + suffix_len` が usize と u32 に収まることを検査する。
- 読みと置換列の全バイトは 0x5F 以下。通常表現の UTF-8・カタカナ検査も維持する。
- 読みの接頭部・置換列・読みの接尾部を借用した 3 片で保持し、文字列を作るときだけ復号する。
  接頭部・接尾部の切り出しは検査後に行い、中間の String は作らない。
- 最終 FEATURES は u32::MAX 以下。オフセットはレコードの先頭を指す u32 のまま。
  全件 verify、アクセス時のエラー、mmap 更新時の一時ファイル＋rename は従来どおり。

## 試作と採否

第一段階は [計測器](../../../scripts/hsd-pronunciation-probe.rs) の単独実験。
信頼できる v5 配布辞書を読み、FEATURES と FEATURE_OFFSETS を変更した実験ファイルを作る。
版は正式な v6 と区別して `5006` とし、現行のリーダーは拒否する。
移行用の変換器ではない。採用する場合の移行は固定した上流からの再構築になる。

全固有素性について、差分を復号して v5 の正準バイト列へ戻し、元レコードと直接比較する。
全エントリのオフセットも元レコード先頭から新レコード先頭へ写す。
他の 16 セクションは変更せず、同点・候補順・未知語・読み補正は形式変更の対象にしない。
容量はパディングを含む完成した実験ファイルと、単一ワーカーの zstd 1.5.7 `-19` を比較する。

単体の復号は、連続・固定 seed のランダム選択各 100 万件を 6 回ずつ、順番を交互にして測る。
この測定は借用した各フィールドの全バイトを読むだけで、カタカナの UTF-8 化や Arc 確保は含まない。
checksum は最適化除去の防止用であり、一致の保証は全固有素性のバイト比較で行う。
ヒープ上の配列の測定で、mmap の初回アクセスや解析全体へは換算しない。

第一段階の推奨辞書は 220,974,766 → 215,245,422B（5,729,344B 減）。
3,358,794 固有素性のうち 760,161 件が差分を使い、すべて復元が一致した。
圧縮の比較と独立レビューを終えてから、実際のリーダーで追加評価するか判断する。
正式採用には次の第二段階が必要になる。

- 借用表現を既存の素性リーダーへ入れた独立した試作で、全フィールドのコーパス比較。
- 3 辞書の混合コーパス解析・初回解析・RSS・圧縮サイズ・構築時間とピーク RSS。
- 壊れた差分・長さ・flags・varint の拒否、feature の各構成、FFI・Python への影響の確認。
- コーパス上で持続的な 3% 以上の CPU 退行がないこと。容量の改善だけでは採用しない。
