# 補正の段の絞り込みの計測（2026-11-07、Issue #119）

結果と判断は [performance.md の 5 章](../../performance.md#5-補正の段の絞り込み2026-11issue-119)。

## 条件

- Windows 11 Home 10.0.26300、AMD Ryzen 7 5700X（8 コア 16 論理 CPU）、Rust 1.98.1
- `scripts/bench-tokenize.py` で論理 CPU 1 個（番号 2）に固定し、3 つの版を交互に 6 回走らせた（1 回目の
  ウォームアップは捨て、版の順は回ごとに反転）。比は v26.10.107 との最小値どうしの比
- 版: v26.10.107 と v26.11.102（どちらもタグのソースから `cargo build --release --locked`）、変更後（この変更の
  ソースから同じく）
- 辞書: 計測時の `ipadic.hsd` を `hasami export` した CSV（390,861 語）と、`scripts/prepare_ipadic.py` が作る
  matrix.def・char.def・unk.def から、v26.10.107 で v5 形式、変更後の版で v6 形式を作った（語彙は同じ。v26.11.102 と
  変更後は同じ v6 の辞書）
- 指標: 解析だけは `bench --file`（全行の解析を 1 回として 3 回の最速の回、Best pass）。プロセス全体は
  `tokenize -f wakachi -j 1`（標準入力から全行。辞書のロードと出力を含む）の QueryProcessCycleTime の
  サイクル（命令数ではない）
- 入力（`--case`、どれも `--repeat 20` で 12 万文）:
  - `issue`: Issue と同じ 20 種の文を数値を変えて並べた 6,000 行（525,601 バイト）
  - `plain`: 補正の錨の文字を含まない 6 種の文
  - `idle`: 錨の文字（日・間）はあるが補正の当たらない 3 種の文
  - `units`: 数量を 3 つ含む文（kg・%・km）を 1 行に 200 文ずつつないだ長い行（文書を 1 回で解析する経路）
  - 実際の文章: 青空文庫・国会会議録・Wikipedia・Wikibooks・Wikinews の手元のコーパス 61,028 行（`--input`。
    公開しないので入力と JSON は置いていない）

## 結果

最小値。括弧の中と「全体」の列は v26.10.107 との比。

| 入力 | 解析だけ v26.10.107 | v26.11.102 | 変更後 | 全体 v26.11.102 | 全体 変更後 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `issue` | 0.621s | 0.791s（+27.4%） | 0.640s（+3.1%） | +25.6% | +4.7% |
| `plain` | 0.435s | 0.554s（+27.4%） | 0.415s（-4.6%） | +23.9% | -5.4% |
| `idle` | 0.426s | 0.546s（+28.2%） | 0.404s（-5.2%） | +24.8% | -5.7% |
| `units` | 0.646s | 1.054s（+63.2%） | 0.982s（+52.0%） | +73.0% | +59.0% |
| 実際の文章 | 1.606s | 2.025s（+26.1%） | 1.732s（+7.8%） | +33.7% | +7.6% |

分かち書きの出力は、合成の 4 条件ではどれも 3 版で同じだった。実際の文章では v26.11.102 と変更後が同じで、
v26.10.107 とは v26.11 の数詞・単位の合成の分だけ違う。実際の文章の回は計測中のマシンの負荷が高く、壁時計の
ばらつきが大きかった（サイクルと Best pass の最小値は揃っている）。

錨の無い入力と、錨はあるが補正の当たらない入力では、v26.10.107 からある段（助数詞の読み、ASCII の数量の
詰め直し）も省けるので、v26.10.107 より速い。`units` はどの区間にも錨があり、補正が実際に掛かるので、
絞り込みはほとんど効かない（v26.11.102 で増えた単位の合成・数量の読みの費用がそのまま残る）。同じ文を 1 行に
1 文ずつ並べても、解析だけで v26.10.107 比 +52.2%（0.655s → 0.997s）で、長い行で費用が二乗に増えることは無かった。
