# HSD v5 の文法共有

v5 は v4 の素性レコードから、品詞・活用型・活用形の組を共有表に分離する。
変更の経緯と計測値は [hsd-format.md](hsd-format.md) に残す。
バイト配置と検査条件の実装は `src/hsd/*.rs` の冒頭コメントと対応する読み書き処理が正。

## コンテナ

magic は `HSMDICT\0`、ヘッダの offset 8 にあるリトルエンディアン u32 の版は `5`。
64B ヘッダ、24B のセクション表要素、64B のセクション境界、既存の flags は v4 と同じ。
セクション id 1〜17 のうち、変更する内容は `FEATURES` (8) と、それを指す
`FEATURE_OFFSETS` (7) のバイトオフセットだけ。必須セクション `GRAMMAR` (18) を加える。
セクション表の順番に依存せず、id で参照する。既存の範囲・重複・整列の検査は維持する。

v1〜v4 は読み込まず、`scripts/build-dict.sh` による再構築を案内する。
v4 を読み書きするライブラリと v5 の辞書を混ぜて使わない。

## GRAMMAR (18)

次の 6B レコードをパディングなしで並べる。すべてリトルエンディアン。

| 要素内の位置 | 型 | 内容 |
| --- | --- | --- |
| 0 | u16 | POS_STRINGS の番号 |
| 2 | u16 | CONJ_TYPE_STRINGS の番号 |
| 4 | u16 | CONJ_FORM_STRINGS の番号 |

ロード時に、領域が空でないこと、長さが 6 の倍数であること、実ポインタが型の境界に合うこと、
要素数が u32 に収まること、各番号が対応する文字列表の範囲にあることを検査する。
`bytemuck::try_cast_slice` を使い、検査なしのポインタ変換はしない。
検査後は mmap 上の表をそのまま参照する。

書き出す順番は、**重複を除いた素性レコードで数えた**組の出現回数の降順。
同数なら `(pos_id, conj_type_id, conj_form_id)` の辞書順にする。
エントリ数やコーパス内の頻度で重み付けしない。復号は表の並び順に依存しない。

## FEATURES (8)

レコードは `grammar_id: varint(u32), flags: u8, 読み, [発音], [原形]`。
v4 の先頭にあった 3 個の u16 を、GRAMMAR の 0 始まりの番号に置き換える。
番号は unsigned LEB128（最大 5B）。5 バイト目は下位 4 ビットだけを値に使う。
切り詰め、6B 以上、u32 の範囲外、GRAMMAR の範囲外はアクセス時に `DictError::Corrupt` にする。
書き手は最短表現を出す。読み手は u32 に収まる冗長な表現も許容する。

flags と文字列の意味は v4 と同じ。

- bit 0: 原形が表層形と同じなので原形を省略する。
- bit 1: 発音が読みと同じなので発音を省略する。このとき bit 3 は 0。
- bit 2 / 3: 読み / 発音をカタカナ詰めで保持する。
- bit 4〜7 は 0。

文字列は符号化後のバイト長（u32 の LEB128）と本体。
カタカナ詰めは U+30A0〜U+30FF を `cp - 0x30A0` の 1B に写す。
それ以外の文字列は UTF-8。空文字列はカタカナ詰めにしない。
文字列の範囲・UTF-8・詰めた値・flags の妥当性は引き続きアクセス時に検査する。

FEATURE_OFFSETS はエントリごとの u32 バイトオフセットのまま。
最終 FEATURES は u32::MAX バイト以下とし、書き出し時に検査する。
品詞・活用型・活用形の各番号は u16 のままだが、組の数に 65,536 の上限を追加しない。

## 構築と回帰の条件

構築時は文法の 3 番号と残りのデータを正準キーとして重複を除き、素性番号を割り当てる。
その後に共有表を確定して各素性を詰め直し、エントリの素性番号をバイトオフセットに変換する。
中間領域の位置は usize とし、最終形式の 4GiB 上限を中間領域に誤って適用しない。
詰め直す前に重複排除用のマップを解放し、最終サイズを数えて領域を一度だけ確保する。

候補の順番、同点の選択、未知語、読み補正、公開 Token のフィールドは変えない。
trie・接続行列・文脈 ID・文字種・未知語テンプレートも v4 と同じ。
merge / repair は v5 の編集可能な辞書を読み、従来どおり一時ファイルと rename で v5 を書く。
配布辞書は旧バイナリの変換で移行せず、固定した上流ソースから再構築する。
