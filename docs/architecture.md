# 解析の仕組み

hasami は入力を文字単位の double-array trie で辞書引きし、未知語の候補と一緒にラティスに並べる。そこから Viterbi で、
接続コストと単語コストの和が最小になる並びを選ぶ（流れの図は [README の「アーキテクチャ」](../README.md#アーキテクチャ)）。
この文書は、空白と未知語の扱いを MeCab と比べて説明する。辞書の形式は [dictionaries.md](dictionaries.md) の
「辞書形式 (.hsd)」、速くしたときの記録は [performance.md](performance.md) にある。

## 空白

半角空白・タブ・改行（char.def の SPACE の文字）は、MeCab と同じく読み飛ばしてトークンにしない。空白の前後の語は
直接つながるので、「データを CSV で出力する」の「で」は空白の後ろでも格助詞のまま（空白をノードにしていたときは、
記号,空白 からの接続コストが低い接続詞になっていた）。トークンの `start` / `end` は入力のバイト位置なので、
空白はトークンの間の隙間になる（表層形をつなげても入力には戻らない）。全角の空白は IPAdic では辞書の語
（記号,空白）なのでトークンになる（MeCab と同じ）。

## 未知語

未知語の候補は MeCab と同じく char.def の group・length で作る（同じ文字種の並び全体と、1〜length 字の接頭辞）。
候補ごとに unk.def の文字種のテンプレート（IPAdic の英字・カタカナ・漢字・ひらがなは、普通名詞・固有名詞の
地域 / 組織 / 人名 / 一般・感動詞などの 6〜7 個）の数だけノードを作り、品詞は前後の語との接続コストで決まる
（MeCab と同じ。「Zoomの会議」の「Zoom」は 名詞,固有名詞,組織）。テンプレートを全部使うと、未知語のノードが増えて
解析の時間は約 15% 増える。MeCab と違うのは次の 3 点。

- **カタカナの複合語**: 並び全体の未知語は単語コストが一律（IPAdic で 9461）なので、既知語 2 語以上の複合語に勝ちやすい
  （MeCab + NEologd は「オススメアプリ」「ソフトバンクステージヨドバシ」を 1 つの未知語にする）。hasami は、カタカナの
  並び全体の候補（3 字以上）を、3 字以上の既知語を隙間なく並べて覆えるなら作らない。最初の語は並びの前から始まってよく
  （「音ゲー / アプリ」）、最後の語は並びの後で終わってよい（「スパッと」）。2 字以下の語は数えないので、辞書に無い人名
  などは断片に割れず 1 語のまま（「ドミニク」を「ドミ / ニク」にしない）
- **辞書の語と同じ表層のカタカナの未知語**: 単語コストの高い既知語（IPAdic の「キャンプ」16437、「コーチ」16149）は
  並び全体の未知語に負ける。最良パスに残ったカタカナの未知語（3 字以上）と同じ表層の語が辞書にあれば、分け方は
  そのままで、品詞・読みなどをその語から取る（同じ表層のエントリが複数あれば、前後の語との接続コストと単語コストの和が
  最小のもの）。`is_known` は true、`word_cost` はラティスで使った未知語の値
- **長い並び**: MeCab は 25 字を超える並びを 1 つの候補にしない（`max-grouping-size`）が、hasami は長さによらず 1 つにする
  （32 字の英字の ID が 1 字ずつと既知語の断片に割れない）

ニュース 13 万行を推奨辞書で解析し、以前の実装（並び全体の候補を 2 字で打ち切っていた）と語の境界が食い違う箇所を数えた。

| 食い違い | MeCab と同じ候補だけ | 上の規則を足した後 |
| --- | ---: | ---: |
| 既知語の並び → 1 語（オススメ / アプリ → オススメアプリ） | 9,787 | 5,528 |
| 断片 → 1 語（ク / オリ / ティ → クオリティ。以前の誤りが直った箇所） | 2,075 | 2,056 |
| 既知語が未知語を含む並びになる・既知語 1 語が割れる | 45 | 13 |

残る「既知語の並び → 1 語」は、2 字以下の語を含む複合語（ポータブルナビ、カロリーオフ）と、辞書に無い人名など
（レナード、ホアキン）。

## 読みと字幅

読みが欠けた仮名のトークンは表層形から補う。半角カナと結合濁点・半濁点も扱う
（`ｶﾞｯｺｳ` → ガッコウ）。全角英字も ASCII と同じ綴り読み・数字と隣接する場合の単位読みの対象になる。
入力と辞書キーは書き換えず、表層形と UTF-8 バイト位置を保つ。
結合文字が別のトークンに分かれた場合まで入力全体を正規化する機能ではない。

英字の文脈補正では、数字の `end` と英字の `start` が一致するときだけ単位読みを付ける。
`3F` の F はファラド、`3 F`・タブや改行で離れた F はエフになる。
`100km`・`3GB`・`5V` は単位読み、`100 km`・`3 GB`・`5 V` はケーエム・ジービー・ブイの綴り読みになる。
既知語で 3 文字以上の英字にカタカナの読みがある場合は、従来どおり辞書の読みを優先する（`NASA` → ナサ）。

数詞と隣接する助数詞の読み・発音には音便を反映する。本・杯・匹、回・個、分と、位の数詞の百・千が対象で、
「三本」はサン / ボン、「一回」はイッ / カイ、「三百本」はサン / ビャッ / ポンになる。
時・時間の四・七・九もヨ・シチ・クに直す。IPAdic 体系の数詞・助数詞を対象に、数詞の末尾と助数詞の読みを表で照合する。
固有名詞や対応表にない読み、空白・タブ・改行で離れた語は補正しない。
複数字の漢数字も字ごとの標準読みと内部の百・千の音便を確認し、「十一」がテンイチなら補正しない。
IPAdic で未知の普通名詞になる「ぷん」は、仮名から補完したプンのときだけ例外として扱う。

人・日の和語読みは数詞列全体を確認する。一人・二人はヒト / リ、フタ / リ、二日〜十日と十四日・二十四日は
フツ / カ、ミッ / カなどにする。八日の読みはヨウ / カ、発音はヨー / カで、各トークンに空でない読みを残す。
十二人・十三日には和語読みを適用しない。和語読みの対象外の日の七・九はシチ・クにし、十七日はジューシチニチになる。
数詞列全体が標準の読み・発音のときだけ和語読みにし、十がテンなどの別読みなら変更しない。
一日のツイタチは日付と期間を区別できないので補正せず、
二十日のハツカも現在のトークンに分配しない。小数点（点・`.`・`．`）以下には音便・和語読みを適用しない。
一語の「十分」の直後に「前」「後」が隣接する場合はジュップンに直すが、「十分に」「十分な」は変えない。
数詞と助数詞の音便・和語読みの補正は読み・発音だけを変更し、表層形・品詞・原形・位置・コスト・辞書由来の情報を保つ。
ASCII 数字は、助数詞・年度・位の数詞（百・千・万・億・兆）や許可した英字単位に隣接する数量だけを位取りで読む。
`10分` はジュップン、`2031年度` はニセンサンジューイチネンド、`1,000円` はセンエン、`2.5倍` はニテンゴバイになる。
原入力から数や識別子の候補全体を調べてから、数の範囲だけを一つのトークンにする。カンマは整数部の正常な3桁区切りだけを
認め、小数点は1つで両側に数字が必要。整数部・小数部はそれぞれ16桁まで（総数32桁まで）で、整数は兆まで扱う。
小数部は1桁ずつ読み、小数の後の助数詞には音便・和語読みを適用しない。整数の一・八・十の後の兆は促音化する。
この位取り読みと兆の促音補正は、保護した識別子や不正な数字列には適用しない。従来の1桁数字と助数詞の音便は維持する。
兆の直前の数詞列は純ASCIIまたは純漢数字に限り、全角数字や混在した列（`1８兆`・`1八兆`）の既存出力は保つ。

単独の数、先頭ゼロの数字列、符号付きの数、電話・郵便番号、IP・版番号、不正なカンマや複数の小数点は合成しない。
英字の識別子の後の数は空白・改行越しでも保護し、数字列の中に全角数字や漢数字を含む混在表記（`123４` など）も合成しない。
英字単位は既存の単位表で仮名の読みを持つ語との完全一致だけを認め、`10ms` を `10m` として部分認識しない。
数と単位が空白・改行で離れている場合も合成しない。一方、`10万2031円` のように和文の単位でつながる数量はそれぞれ読む。
Analyzer の前分割や文ごとの API でも元の入力を使って判定する。`LatticeWorkspace::tokenize_into` を直接呼ぶ場合は
渡した入力だけを文脈として使い、既存の出力は判定・変更の対象にしない。

合成トークンの表層形と原形はカンマ・小数点を含む原入力の部分文字列、位置はその全体のバイト範囲になる。
品詞は `名詞,数,*,*`、活用型・活用形は空、`is_known` は false。
`word_cost` は元トークンのコストを広い整数型で足し、最後に一度だけ i16 の範囲に飽和させる。最良パス決定後の情報であり、
経路の再探索には使わない。もともと数詞1トークンなら既存の素性を維持し、非空の既知の読みも尊重する。
`2026年度`・`2.5倍` のように数と単位を含む既知語も、分割や素性を変更しない。

暦月は別に、半角空白・タブを挟む `9 月`・`９ 月`・`九 月` をク / ガツに補正する。
1〜12の半角数字・全角数字・漢数字の通常表記を対象に、四・七・九はシ・シチ・ク、十の発音はジューにする。
数詞が一語なら読み・発音以外を保つ。`1 / 2 / 月` のような数詞列は数の部分だけを数量と同じ形の一語にまとめ、
`12` と `月` の表層形・バイト範囲には空白を含めない。「月」の品詞・原形なども保つ。
数詞・月の品詞と既存の標準読みを確認し、未知のASCII数詞だけは空の読みも補う。
一般の月、`3か月`、`月間`・`月曜`、小数・識別子・先頭ゼロ・混在表記・13以上、改行・全角空白を挟む形は対象にしない。
空白のない既知の月名は辞書のままにする。人名が数詞と普通名詞に分かれる場合など、同じ表記の意味を判別するものではない。

対応表は [Open JTalk 1.11 の数詞規則](https://github.com/r9y9/open_jtalk/blob/1.11/src/njd_set_digit/njd_set_digit_rule_utf_8.h)
を参考に、トークンの読みを補正する独立した処理として実装している。

補助平面の CJK 拡張漢字・互換漢字も、char.def の明示指定がなければ漢字として未知語候補を作る。
