# 解析の仕組み

hasami は入力を文字単位の double-array trie で辞書引きし、未知語の候補と一緒にラティスに並べる。そこから Viterbi で、
接続コストと単語コストの和が最小になる並びを選ぶ（流れの図は [README の「アーキテクチャ」](../README.md#アーキテクチャ)）。
この文書は、空白と未知語の扱いを MeCab と比べて説明する。辞書の形式は [dictionaries.md](dictionaries.md) の
「辞書形式 (.hsd)」、速くしたときの記録は [performance.md](performance.md) にある。

## 空白

半角空白・タブ・改行（char.def の SPACE の文字）は、MeCab と同じく読み飛ばしてトークンにしない。空白の前後の語は
直接つながるので、「データを CSV で出力する」の「で」は空白の後ろでも格助詞のまま（空白をノードにしていたときは、
記号,空白 からの接続コストが低い接続詞になっていた）。トークンの `start` / `end` は入力のバイト位置なので、
空白はトークンの間の隙間になる（表層形をつなげても入力には戻らない）。全角の空白は IPAdic では辞書の語
（記号,空白）なのでトークンになる（MeCab と同じ）。

## 未知語

未知語の候補は MeCab と同じく char.def の group・length で作る（同じ文字種の並び全体と、1〜length 字の接頭辞）。
候補ごとに unk.def の文字種のテンプレート（IPAdic の英字・カタカナ・漢字・ひらがなは、普通名詞・固有名詞の
地域 / 組織 / 人名 / 一般・感動詞などの 6〜7 個）の数だけノードを作り、品詞は前後の語との接続コストで決まる
（MeCab と同じ。「Zoomの会議」の「Zoom」は 名詞,固有名詞,組織）。テンプレートを全部使うと、未知語のノードが増えて
解析の時間は約 15% 増える。MeCab と違うのは次の 3 点。

- **カタカナの複合語**: 並び全体の未知語は単語コストが一律（IPAdic で 9461）なので、既知語 2 語以上の複合語に勝ちやすい
  （MeCab + NEologd は「オススメアプリ」「ソフトバンクステージヨドバシ」を 1 つの未知語にする）。hasami は、カタカナの
  並び全体の候補（3 字以上）を、3 字以上の既知語を隙間なく並べて覆えるなら作らない。最初の語は並びの前から始まってよく
  （「音ゲー / アプリ」）、最後の語は並びの後で終わってよい（「スパッと」）。2 字以下の語は数えないので、辞書に無い人名
  などは断片に割れず 1 語のまま（「ドミニク」を「ドミ / ニク」にしない）
- **辞書の語と同じ表層のカタカナの未知語**: 単語コストの高い既知語（IPAdic の「キャンプ」16437、「コーチ」16149）は
  並び全体の未知語に負ける。最良パスに残ったカタカナの未知語（3 字以上）と同じ表層の語が辞書にあれば、分け方は
  そのままで、品詞・読みなどをその語から取る（同じ表層のエントリが複数あれば、前後の語との接続コストと単語コストの和が
  最小のもの）。`is_known` は true、`word_cost` はラティスで使った未知語の値
- **長い並び**: MeCab は 25 字を超える並びを 1 つの候補にしない（`max-grouping-size`）が、hasami は長さによらず 1 つにする
  （32 字の英字の ID が 1 字ずつと既知語の断片に割れない）

ニュース 13 万行を推奨辞書で解析し、以前の実装（並び全体の候補を 2 字で打ち切っていた）と語の境界が食い違う箇所を数えた。

| 食い違い | MeCab と同じ候補だけ | 上の規則を足した後 |
| --- | ---: | ---: |
| 既知語の並び → 1 語（オススメ / アプリ → オススメアプリ） | 9,787 | 5,528 |
| 断片 → 1 語（ク / オリ / ティ → クオリティ。以前の誤りが直った箇所） | 2,075 | 2,056 |
| 既知語が未知語を含む並びになる・既知語 1 語が割れる | 45 | 13 |

残る「既知語の並び → 1 語」は、2 字以下の語を含む複合語（ポータブルナビ、カロリーオフ）と、辞書に無い人名など
（レナード、ホアキン）。

## 読みと字幅

「長さ」「距離」「全長」に直結した半角整数の距離と、`m` に続く分・秒の列が揃う場合は、
`長さ720m3分26秒` の `3` を体積単位へ取り込まない。分・秒は0〜59、先頭ゼロのない1〜2桁とし、
前後の文境界と元入力の連続性を確認する。境界をまたぐ辞書候補が標準の `m2`・`m3` だけである場合に限り、
その位置でラティスを区切り、既存の数量規則で距離の単位と時間の助数詞を読む。
辞書にある候補の品詞・原形・コストなどは保持する。
独自読みや長い既知語、識別子、引用・括弧、上付き指数、分数・割合、不完全な時間列へは適用しない。
数量の照会は従来の全文検証を維持し、保護されていた列の途中を単独の数量として再認可しない。

既知の「震度7」が「シンドセブン」と選ばれた場合、標準の「を観測した」「を記録した」と
前後の文法境界が揃う測定構文だけで「シンドナナ」へ補正する。「最大」の前接も認める。
対象と周辺語の素性・連続した元入力の範囲を確認し、品詞・原形・位置・コスト・既知未知は保つ。
引用・括弧の範囲は必要なときに全文から一度だけ求め、前分割をまたぐ内側も保護する。
裸の語、題名・作品名などのラベル、独自読み、識別子へ補正を広げず、辞書の名称候補も残す。

読みが欠けた仮名のトークンは表層形から補う。半角カナと結合濁点・半濁点も扱う
（`ｶﾞｯｺｳ` → ガッコウ）。全角英字も ASCII と同じ綴り読み・数字と隣接する場合の単位読みの対象になる。
入力と辞書キーは書き換えず、表層形と UTF-8 バイト位置を保つ。
結合文字が別のトークンに分かれた場合まで入力全体を正規化する機能ではない。

英字の文脈補正では、数字の `end` と英字の `start` が一致するときだけ単位読みを付ける。
`3F` の F はファラド、`3 F`・タブや改行で離れた F はエフになる。
`100km`・`3GB`・`5V` は単位読み、`100 km`・`3 GB`・`5 V` はケーエム・ジービー・ブイの綴り読みになる。
既知語で 3 文字以上の英字にカタカナの読みがある場合は、従来どおり辞書の読みを優先する（`NASA` → ナサ）。

入力全体で標準の ASCII 数詞と単位全体を確認できる場合、未知の半角英字単位に残った
`名詞,固有名詞,組織,*` を、合成した単位と同じ `名詞,接尾,助数詞,*` にそろえる（`75kW` の `kW` など）。
既知語・独自読み・標準でない素性や、型番・識別子の境界は保護する。
単位の品詞以外の素性を保ち、読みと発音には従来の単位読み補完を使う。
分離した数詞と未知の `cm`・`kg`・`km` には、普通名詞・助数詞と同じ既存の音便規則も適用され、
`170cm` はヒャクナナジュッセンチメートル、`6kg` はロッキログラムとなる。

数詞と隣接する助数詞の読み・発音には音便を反映する。本・杯・匹、回・個、分と、位の数詞の百・千が対象で、
「三本」はサン / ボン、「一回」はイッ / カイ、「三百本」はサン / ビャッ / ポンになる。
時・時間の四・七・九もヨ・シチ・クに直す。IPAdic 体系の数詞・助数詞を対象に、数詞の末尾と助数詞の読みを表で照合する。
固有名詞や対応表にない読み、空白・タブ・改行で離れた語は補正しない。
複数字の漢数字も字ごとの標準読みと内部の百・千の音便を確認し、「十一」がテンイチなら補正しない。
IPAdic で未知の普通名詞になる「ぷん」は、仮名から補完したプンのときだけ例外として扱う。

人・日の和語読みは数詞列全体を確認する。一人・二人はヒト / リ、フタ / リ、二日〜十日と十四日・二十四日は
フツ / カ、ミッ / カなどにする。八日の読みはヨウ / カ、発音はヨー / カで、各トークンに空でない読みを残す。
十二人・十三日には和語読みを適用しない。和語読みの対象外の日の七・九はシチ・クにし、十七日はジューシチニチになる。
数詞列全体が標準の読み・発音のときだけ和語読みにし、十がテンなどの別読みなら変更しない。
一日のツイタチは日付と期間を区別できないので補正しない。二十日は、保護されていない標準形の二十を
一つの数詞にまとめてハツ / カと読む。第二十日や番号・識別子、明示的な別読みには広げない。
既知の助数詞「日間」が一語で選ばれる場合も、同じ和語の対象にカカンを続ける。一日間はイチニチカンのままにする。
小数点（点・`.`・`．`）以下には音便・和語読みを適用せず、数詞の間の点も得点の助数詞として促音化しない。
一語の「十分」の直後に「前」「後」が隣接する場合はジュップンに直すが、「十分に」「十分な」は変えない。
数詞と助数詞の音便・和語読みの補正は読み・発音だけを変更し、表層形・品詞・原形・位置・コスト・辞書由来の情報を保つ。
頻度を表す「年2回」の年も、一般名詞のままネンへ補正する。単独の年と標準整数の冊・回が直結し、
左が文頭・句読点・括弧・係助詞のは/も、右が文末・句読点・括弧・助詞・助動詞となる場合に限る。
「その年」「ある年」など名詞を修飾する語の後や、暦・年齢、独自読み、小数、先頭ゼロ、識別子には広げない。
全角数字や位を含まない複数桁の漢数字も、この補正では新たに認可しない。読みと発音以外の情報は保つ。
「つ」は一〜九の和語読み、「口」は一・二のヒトクチ・フタクチに対応する。
箱・皿・タバと読む束も、数詞全体が一・二のときだけヒト / フタを使う。二十一箱を末尾の一だけで和語にしない。
句・級・件・期・曲・階・か月類はカ行の音便、点・通・冊・刷・週・週間・章・節・頭・着・足・歳・才は一・八・十の促音を補う。
六点・六頭・六週間などの六はロクのままにする。歩は一・六・八・十・百で促音とポ、三・千・万ではポにする。
校・巻・課・機・箇所類にもカ行の促音を補い、軒は三軒のゲンも扱う。キロ類は一キロのイチを保つ。
センチ類、棟・体・ソクと読む束、隻・席・セキと読む石、勝・戦・尺・寸にも、それぞれの系列の促音を適用する。
ハ行の助数詞は、[国立国語研究所の解説](https://kotoba.ninjal.ac.jp/qa/yokuaru/qa-225/)にある二系列を区別する。
たとえば三遍はサンベン、三拍はサンパクとなる。票・俵には濁音の別読みもあり、選択済みの有効な別読みを保つ。
万票は[放送での確認例](https://www.ytv.co.jp/announce/kotoba/back/3401-3500/3491.html)に沿ってマンビョーとする。
都・府・県は接尾地域の標準読みだけを認め、都府県のように行政区分が連なる語では促音化しない。
号は接尾一般の標準形だけを数量として認める。一般名詞や任意の接尾辞を助数詞として扱うものではない。
新しい音便も、標準の読み・発音と数詞の直結を確認し、小数・識別子・明示的な別読みへ適用しない。
全角数字を含む識別子も、半角数字の識別子と同様に原入力の範囲で保護する。
ASCII 数字は、助数詞・年度・位の数詞（百・千・万・億・兆）や許可した英字単位に隣接する数量と、独立した小数を位取りで読む。
`10分` はジュップン、`2031年度` はニセンサンジューイチネンド、`1,000円` はセンエン、`2.5倍` はニテンゴバイになる。
原入力から数や識別子の候補全体を調べてから、数の範囲だけを一つのトークンにする。カンマは整数部の正常な3桁区切りだけを
認め、小数点は1つで両側に数字が必要。整数部・小数部はそれぞれ16桁まで（総数32桁まで）で、整数は兆まで扱う。
小数部は1桁ずつ読み、小数の後の助数詞には音便・和語読みを適用しない。整数の一・八・十の後の兆は促音化する。
この位取り読みと兆の促音補正は、保護した識別子や不正な数字列には適用しない。従来の1桁数字と助数詞の音便は維持する。
兆の直前の数詞列は純ASCIIまたは純漢数字に限り、全角数字や混在した列（`1８兆`・`1八兆`）の既存出力は保つ。

単独の整数、先頭ゼロの数字列、符号付きの数、電話・郵便番号、IP・版番号、不正なカンマや複数の小数点は合成しない。
単位のない小数（`9.2`・`図9.2`）も小数点を読む。`v9.2`・`ISO 9.2`・`9.2.1` のような識別子は引き続き保護する。
英字の識別子の後の数は空白・改行越しでも保護し、数字列の中に全角数字や漢数字を含む混在表記（`123４` など）も合成しない。
英字単位は既存の単位表で仮名の読みを持つ語との完全一致だけを認め、`10ms` を `10m` として部分認識しない。
数字の前に単独のカンマだけがある場合は句読点として除き、その後の数量・小数を認識する。
`A,10円` のように同じ英数字区間に字母を含む場合や、不正な桁区切り・先頭の符号は従来どおり保護する。
数と単位が空白・改行で離れている場合も合成しない。一方、`10万2031円` のように和文の単位でつながる数量はそれぞれ読む。
Analyzer の前分割や文ごとの API でも元の入力を使って判定する。`LatticeWorkspace::tokenize_into` を直接呼ぶ場合は
渡した入力だけを文脈として使い、既存の出力は判定・変更の対象にしない。

独立した ASCII 負小数は、入力全体の境界を検査したうえで、分離した標準の記号 `-` の読み・発音をマイナスへ補う。
同じ範囲の標準数詞と小数点からなる本体は、符号を除く生の小数一語へまとめて位取りで読む。
`-0.5` はマイナスゼロテンゴとなり、整数部分の位取りと小数部分の桁読みには既存の小数処理を使う。
文頭・開括弧・区切りの後に限り、英字や ID ラベルの後、識別子・演算子が続くもの、不正な小数は対象にしない。
読み・発音が両方空の未知記号 `-`・`.` も、表層と原形が同じ一文字、記号の品詞、空の活用情報を確認して補う。
符号の表層・品詞・位置・原形・コスト・既知未知は保持し、合成した本体の素性はほかの ASCII 数量と同じにする。
既知の一語、独自の読みや素性、整数・Unicode の符号などへ広げず、識別子の保護範囲も変更しない。

ASCII の等号 `=` に続く負小数には、選択済みの標準的な符号付き整数の別表記が先頭にある場合だけ、別の合成を行う。
例は `=-123.045` の既知語 `-1`（原形 `−1`、一般の固有名詞、標準のマイナスイチ）と標準数詞・小数点の列である。
元入力全体で等号、数値の終端、名前・作品名・数列・ID のラベル、引用・括弧の外側を検査する。等号と符号の間の水平空白は許す。
全トークンの原入力上の連続性、原形・品詞・空の活用情報・標準の読みと発音を照合し、負小数全体を一つの数詞へまとめる。
表層と原形は符号を含む元の ASCII、位置はその全範囲、品詞は `名詞,数,*,*`、活用情報は空、`is_known` は false になる。
コストは符号付きの既知語も含めて選択元を一度ずつ足し、最後に一度だけ i16 へ飽和させる。符号を別の架空トークンへ分解しない。
裸の既知語、既知の小数全体、独自素性、符号が分離した従来の経路と周辺トークンは保持する。
直後の選択済みトークンが助数詞の品詞、または既存の助数詞規則に該当する場合も、水平空白の有無によらず保留する。
`=-3.8本` などで元の末尾数詞と助数詞に対する音便・素性を保持するため、この新しい合成は独立した値に限る。
残部にも標準数詞の条件を要求するため、`=-12.045` で `2.0` が固有名詞のニーテンゼロとして選ばれる場合は合成しない。
この補正で公開の数量・文脈読みの照会 API の対象は増やさない。

ASCII数量の合成トークンの表層形と原形はカンマ・小数点を含む原入力の部分文字列、位置はその全体のバイト範囲になる。
品詞は `名詞,数,*,*`、活用型・活用形は空、`is_known` は false。
`word_cost` は元トークンのコストを広い整数型で足し、最後に一度だけ i16 の範囲に飽和させる。最良パス決定後の情報であり、
経路の再探索には使わない。もともと数詞1トークンなら既存の素性を維持し、非空の既知の読みも尊重する。
`2026年度`・`2.5倍` のように数と単位を含む既知語も、分割や素性を変更しない。

カタカナの数量は、標準の既知語が連続する「面積＋は／が／も＋数詞別表記＋ヘイホー＋メートル＋です」だけを
面積として合成する。数詞別表記のASCII整数の原形と、既存の位取り規則で生成した標準読み・発音を照合する。
任意のカタカナから数を推測せず、IPAdicで全体が未知語になる場合は保持する。前後の文境界（日本語・ASCIIの句点を含む）、
元入力の連続性と全語の素性を確認し、名称・引用・括弧・識別子・独自読み・既知の全体語は対象にしない。
引用の範囲はほかの文脈補正と同じ遅延索引を使い、前分割をまたいでも一度の解析で共有する。

この規則の数詞は表層と位置・ASCII原形・元コストを保ち、標準の読み・発音と `名詞,数,*,*` を持つ。
単位は元の表層「ヘイホーメートル」と範囲を保ち、原形「平方メートル」、標準読み・発音、`名詞,接尾,助数詞,*` を持つ。
どちらも活用情報は空で、`is_known=false` の合成結果になる。単位のコストは元の2語の和を一度だけi16に飽和させる。
辞書の元候補は残し、単一数量・数量範囲・文脈読み範囲の公開照会の認可条件は広げない。

純全角の2〜16桁の整数も、標準の一文字助数詞に直結するときは数詞を一語に合成して位取りで読む。
`１８歳` はジュウハッサイ、`２０回` はニジュッカイになる。入力全体で数字列と助数詞の終端を確認し、
先頭ゼロ・単独の数字列・識別子・混在した字種・既知の一語は保つ。小数、年度・時間・日間などの
複数文字の接尾辞や ASCII 単位は合成対象に含めない。新しく合成した `２０` が標準の日に続く場合はハツカとし、
既知語や未合成の全角数詞をこの条件へ広げない。合成時の表層・原形は元の全角表記で、位置・コスト・既知未知の
扱いは ASCII 数量と同じ（`src/numeric/fullwidth.rs`）。

純全角の年には、1〜12の月と任意の1〜31の日が直結する暦の形も認める（`２０１６年１１月１日`など）。
この追加の認可では、年・月・日ごとに半角か全角の数字へ統一し、先頭ゼロ・混在・範囲外の月日を除外する。
年は従来どおり純全角2〜16桁とし、名前・識別子・引用・括弧の内側や、後続のID・人名としての用法も保護する。
全文で認定した年の開始・終端を保持し、その範囲と一致する標準数詞・既知の年の素性を照合してから既存の合成へ渡す。
年の後でチャンクが分かれても、全文の認可と新しい範囲に必要な厳密検査を失わない。
単独の全角数量と従来の年読み補正の認可条件は維持し、末尾4は既存の年読み規則でヨネンにする。
月と日の語境界・全素性は保持する。年が改善しても日付全体の読みを保証せず、公開数量照会の認可も広げない。

位を省いた漢数字の数量（`二〇四二年`・`六〇〇円`）も、数字部分を一つの数詞にして位取りで読む。
二〜十六桁の純粋な漢数字で〇・零を含む数量か、三桁以上の年・年度に限る。
ゼロなしの二字列は概数・範囲・固有名詞と区別し、後述の確認済みの組だけを例外とする。
数詞の品詞・字ごとの標準読み・原入力の連続した範囲と、直後の助数詞も確認する。
位付きの漢数字は、標準の日に直結した二十だけを例外として合成する。既知の数詞一語の二十も、この限定条件では
後段の和語読みへ渡すため合成する。二十日を含む既知語や人名、他の位付きの数へは適用しない。
先頭ゼロ、単独の数字列、固有名詞、番号・型番・版、混在した字種、小数は合成しない。
この二十を除く既知の数詞一語と、数・単位を含む既知語の非空の読みは保持する。
合成語の位置・原形・コスト・既知未知の扱いは ASCII 数量と同じ。
候補の開始位置は前分割前の入力で決めるため、空白・改行を挟む英字の前置をチャンクごとに忘れない。

二字列の例外は `一一`・`一六`・`一八`・`二一`・`三八`・`四一`・`四八` と、標準の
`歳`・`才`・`か月`・`カ月`・`ヶ月`・`キロ`・`キログラム`・`キロメートル` の組に限る。
`一八か月` はジュウハッカゲツになる。既知の数詞一語や別読みを持つ語は保ち、日付・概数全般へ適用しない。
`二八` には十六歳を表す語義もあるため、二十八へ合成せず、値を解釈しないまま末尾の八だけに音便を足すことも避ける。
和文に続くカンマは限定して数量の区切りとみなすが、英字・数字・識別子ラベルに続くカンマは認可しない。

標準の整数数詞に既知の助数詞 `年（ネン）` が直結するときは、末尾の四をヨに補正する（`src/numeric/year.rs`）。
`14年` はジュウヨネンになる。入力全体で開始位置と年の終端を確かめ、数詞列全体の標準読みと原形を検査する。
変えるのは末尾の読み・発音だけで、年の素性やコストは保つ。識別子・小数・既知の一語・明示された別読み・年度などは対象にしない。

暦月は別に、半角空白・タブを挟む `9 月`・`９ 月`・`九 月` をク / ガツに補正する。
1〜12の半角数字・全角数字・漢数字の通常表記を対象に、四・七・九はシ・シチ・ク、十の発音はジューにする。
数詞が一語なら読み・発音以外を保つ。`1 / 2 / 月` のような数詞列は数の部分だけを数量と同じ形の一語にまとめ、
`12` と `月` の表層形・バイト範囲には空白を含めない。「月」の品詞・原形なども保つ。
数詞・月の品詞と既存の標準読みを確認し、未知のASCII数詞だけは空の読みも補う。
一般の月、`3か月`、`月間`・`月曜`、小数・識別子・先頭ゼロ・混在表記・13以上、改行・全角空白を挟む形は対象にしない。
空白のない既知の月名は辞書のままにする。人名が数詞と普通名詞に分かれる場合など、同じ表記の意味を判別するものではない。

空白のないASCIIの `1月`〜`12月` には別の認定規則を使う。全文から数詞と月の開始・終端を索引し、
前置する名前や識別子のラベル、数字列、引用・括弧の内側、先頭ゼロ、範囲外、`月間`・`月曜`・`月額`などを除外する。
選択された標準の数詞と既知の「月」の全素性・原入力の範囲を照合し、数詞一語なら読み・発音だけを、
複数の数字なら数詞の範囲だけを既存の飽和コスト和・`is_known=false`の一語にする。
「月」は読み・発音をガツにして、ほかの素性を保つ。既知の全体語、独自の素性や読み、全角の既知月名は変更しない。
裸の数詞だけに一致する保護範囲は認定後に扱うが、識別子など広い保護範囲は迂回しない。
この索引は上の空白付き・漢数字の月の索引と分け、公開数量照会の認可条件も広げない。
`2024年11月1日`では年と日の全素性を保持し、月が補正されたことだけで日付全体の読みを保証しない。

位を省いた `一一月` は、既知の数詞「一」に標準の「一月」などが連続するとき、先頭の一の読み・発音だけを
ジュウ・ジューへ補正する。後続の日付の読みや既知語の分割は保つ。開始位置を入力全体で確認し、
引用内・人名や識別子の前置・数字列の途中・人名接尾辞・月間などの別語へ続く形は対象にしない。

対応表は [Open JTalk 1.11 の数詞規則](https://github.com/r9y9/open_jtalk/blob/1.11/src/njd_set_digit/njd_set_digit_rule_utf_8.h)
を参考に、トークンの読みを補正する独立した処理として実装している。

成句の一部は、連続した表層形・品詞・原形・活用形が揃うときだけ読みを補正する（`src/lattice/idiom.rs`）。
対象は既知語の確認済みの読みの組に限り、他のフィールドや辞書の別読みは変更しない。
句読点・引用・空白・識別子の保護範囲をまたぐ照合はせず、成句に似た時間範囲や複合語の末尾も除外する。
語義を一般に判定する処理ではない。たとえば修飾された身を粉末にする字義通りの用法を変えないため、
「身」の前が連体修飾になり得る形なら保守的に補正を見送る。

終止形の述語から「か」「とか」へ続く列挙では、既知の人名として選ばれた「等（ヒトシ）」を、
副助詞の「等（ナド）」へ補正する（`src/lattice/particle.rs`）。連続した標準の素性と、後続が
文末・句読点・閉括弧・係助詞「も」のいずれかであることを確認する。変えるのは品詞・読み・発音だけで、
元の単語コストは保つ。名詞や姓の後、別読み、識別子の保護範囲を含む形は対象にしない。

和文から始まる既知語が数字で終わり、その数字列が入力で続いている場合は、途中で終わる候補を使わない。
英字・数字・符号で始まる型番や小数などには広げず、辞書が持つ読みを保つ。

補助平面の CJK 拡張漢字・互換漢字も、char.def の明示指定がなければ漢字として未知語候補を作る。
